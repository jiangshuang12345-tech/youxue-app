# VIPKID 优学个人中心——课时与订单 PRD

| 项目 | 内容 |
|---|---|
| 产品名称 | VIPKID 优学 |
| 需求名称 | 个人中心课时与订单能力 |
| 文档版本 | V1.0 |
| 文档日期 | 2026-08-24 |
| 目标终端 | iPhone 横屏 |
| 需求状态 | 待评审 |

## 1. 需求背景

当前个人中心主要展示用户信息、学习数据与会员权益，缺少课时资产和订单记录的集中查询入口。用户无法快速确认剩余课时、课时有效期、课时获得与消耗明细，也无法在应用内统一查看购买订单及订单详情。

本需求在个人中心新增“我的课时”和“我的订单”两个入口，建立从资产概览到明细追溯的完整查询链路。所有页面以 iPhone 横屏为主要展示形态。

## 2. 产品目标

1. 用户可在个人中心一键进入课时资产与订单中心。
2. 用户可明确查看不同课时类型的剩余数量和有效期。
3. 用户可追溯课时包批次，以及每次课时获得和消耗记录。
4. 用户可按状态查看订单，并进入单笔订单详情。
5. 横屏页面在一个视口内优先展示核心信息，列表区域独立滚动。

## 3. 非目标

- 本期不支持购买课程或课时。
- 本期支持待支付订单继续支付；暂不支持主动发起退款申请。
- 本期隐藏发票与协议入口，不提供开票或协议下载能力。
- 本期不支持修改课时有效期或人工调整课时。
- 本期不包含后台运营配置能力。

## 4. 用户角色与使用场景

### 4.1 用户角色

- 已登录家长用户：查看孩子名下课时资产及购买订单。
- 多学员家庭：后续可按当前选中的学员查询数据；本期默认展示当前学员。

### 4.2 核心场景

- 家长上课前确认剩余课时是否充足。
- 家长确认课时包何时到期，合理安排上课计划。
- 家长核对某笔课时是购买、赠送还是上课消耗。
- 家长确认订单是否支付成功、完成、退款或仍在处理中。
- 家长根据订单编号、时间和金额与客服沟通。

    ├── 已退款

## 6. 页面需求

### 6.1 个人中心

#### 页面目标

为课时资产和订单记录提供稳定、易发现的一级入口。

#### 新增元素

| 元素 | 展示 | 交互 |
|---|---|---|
| 我的课时 | 图标＋文案，可带 NEW 标识 | 点击进入“我的课时” |
| 我的订单 | 图标＋文案 | 点击进入“我的订单” |

#### 规则

- 两个入口与账号管理、隐私协议、关于我们并列。
- 入口点击热区应覆盖图标与文案整体。
- 页面返回后保留个人中心默认滚动位置。

### 6.2 我的课时

#### 页面目标

按课时类型展示当前可用资产。

#### 页面结构

- 顶部：返回按钮、页面标题、说明文案。
- 汇总区：所有课时类型的可用课时总数。
- 课时列表：每种课时类型一张横版卡片。
- 底部：课时到期提示。

#### 课时类型

1. 双师智学课课时。
2. 双师智学体验课课时。

#### 字段

| 字段 | 格式 | 必填 | 说明 |
|---|---|---|---|
| 课时类型 | 文本 | 是 | 课时资产分类名称 |
| 剩余课时 | 非负整数 | 是 | 当前可用数量 |
| 有效期 | `YYYY-MM-DD HH:mm:ss` | 是 | 当前课时类型最近或统一有效期 |
| 类型图标 | 图片/图标 | 是 | 用于快速识别类型 |

#### 交互

- 点击“去查看”进入该课时类型的有效期详情。
- 点击课时数字、“剩余课时”或右侧箭头进入课时明细。
- 点击返回按钮回到个人中心。

### 6.3 有效期详情

#### 页面目标

展示课时类型下各课时包批次的激活状态与有效期。

#### 横版布局

- 左栏：课时类型、总剩余课时和消耗规则。
- 右栏：按到期顺序展示课时包卡片；区域独立纵向滚动。

#### 课时包字段

| 字段 | 说明 |
|---|---|
| 激活状态 | 未激活或已激活 |
| 剩余课时 | 当前批次可用课时 |
| 购课日期 | 课时包获得日期 |
| 有效期 | 未激活时展示“激活后计算有效期”；已激活时展示到期时间 |
| 订单编号 | 关联购买订单编号 |
| 来源标签 | 如“购买课程包” |

#### 排序规则

- 已激活批次按有效期从近到远排序。
- 未激活批次按购课日期从早到晚排序。
- 若业务要求“最早到期优先消耗”，前端顺序应与服务端扣减顺序保持一致。

### 6.4 剩余课时明细

#### 页面目标

展示课时获得和消耗流水，支持分类筛选。

#### 横版布局

- 左栏：当前课时类型、累计获得、累计消耗。
- 右栏：筛选栏与流水列表，列表独立滚动。

#### 一级筛选

| 筛选项 | 数据范围 |
|---|---|
| 全部 | 所有获得与消耗记录 |
| 获得 | 仅正向课时记录 |
| 消耗 | 仅负向课时记录 |

#### 二级筛选

仅当一级筛选为“获得”时展示：全部获得、购买获得、赠送获得。

#### 流水字段

- 月份分组。
- 流水标题。
- 发生日期。
- 课时变化量；获得显示 `+N`，消耗显示 `−N`。
- 订单编号；存在关联订单时展示。

#### 状态规则

- 切换一级筛选后，列表回到顶部。
- 离开“获得”后隐藏二级筛选。
- 无数据时展示“当前筛选下暂无课时记录”。

### 6.5 我的订单

#### 页面目标

集中展示当前用户的购买订单，并按状态快速筛选。

#### 横版布局

- 左栏：订单状态导航与各状态订单数量。
- 右栏：双列订单卡片列表，区域独立滚动。
- 不展示“发票和协议”入口。

#### 状态筛选

| 状态 | 说明 |
|---|---|
| 全部订单 | 展示全部订单 |
| 待支付 | 未完成支付或等待确认的订单 |
| 已完成 | 已支付且履约完成的订单 |
| 处理中 | 正在支付确认、发放权益或履约中的订单 |
| 已退款 | 已完成退款的订单 |

#### 订单卡片字段

- 购买人头像和名称。
- 订单状态。
- 订单标题。
- 商品名称。
- 商品数量。
- 实付金额。
- “查看详情”提示。

#### 交互

- 点击左侧状态后，右侧列表即时刷新，选中状态高亮。
- 点击订单卡片任意区域进入订单详情。
- 可取消状态的订单卡片直接展示“取消订单”按钮；点击后弹出二次确认，确认成功后停留在列表并刷新状态。
- 待支付订单卡片展示“微信支付”和“支付宝支付”按钮；点击后分别弹出对应渠道的支付二维码。
- 支付二维码弹窗展示支付方式、应付金额、二维码、有效期提示和关闭按钮；点击遮罩或按 `Esc` 可关闭。
- 支付按钮点击事件不触发订单详情跳转；二维码过期或支付失败时允许关闭后重新发起。
- 无数据时展示“当前状态下暂无订单”。

### 6.6 订单详情

#### 页面目标

展示单笔订单的完整购买、金额和时间信息。

#### 横版布局

- 单一内容卡顶部横向展示订单状态、购买人信息和可用操作。
- 下方展示购买内容、金额与订单信息，不设置独立左栏。

#### 字段

| 模块 | 字段 |
|---|---|
| 状态 | 当前订单状态、状态说明 |
| 用户 | 购买人头像、购买人名称 |
| 商品 | 订单标题、商品名称、商品数量 |
| 金额 | 商品金额、实付金额 |
| 订单信息 | 订单编号、下单时间、支付时间 |

#### 规则

- 未支付订单的支付时间展示“—”。
- 金额统一保留两位小数，格式为 `¥ 0.00`。
- 点击返回按钮回到订单列表，并保留离开前的状态筛选。
- 待支付或确认中的订单展示“取消订单”按钮，其他状态不展示。
- 点击“取消订单”后弹出二次确认；取消成功后状态更新为“已取消”，取消按钮隐藏。
- 已取消订单保留在“全部订单”中，不计入待支付数量。

## 7. 横屏与设备适配要求

- 目标画布比例为 2796×1290，约 2.17:1。
- 原型使用横屏 iPhone 设备外壳展示，内容按设计画布等比缩放。
- 首页主要模块应在一个屏幕内完整可见，不应被放大裁切。
- 灵动岛与 Home 指示条不得遮挡可点击控件或关键文字。
- 详情列表内容超出屏幕时，只滚动列表区域或页面内容，不允许产生横向滚动。
- 最小可点击区域不小于 44×44 pt。

## 8. 数据与接口建议

### 8.1 课时概览

`GET /api/v1/students/{studentId}/lesson-balances`

返回课时类型、余额、有效期与类型标识。

### 8.2 课时包批次

`GET /api/v1/students/{studentId}/lesson-packages?lessonType={type}`

返回批次状态、余额、获得时间、有效期、订单编号和来源。

### 8.3 课时流水

`GET /api/v1/students/{studentId}/lesson-transactions`

建议参数：`lessonType`、`transactionType`、`sourceType`、`cursor`、`pageSize`。

### 8.4 订单列表

`GET /api/v1/users/{userId}/orders`

建议参数：`status`、`cursor`、`pageSize`。

### 8.5 订单详情

`GET /api/v1/orders/{orderId}`

### 8.6 取消订单

`POST /api/v1/orders/{orderId}/cancel`

- 仅允许取消服务端判定为可取消的订单。
- 接口应保证幂等；取消失败时保留原状态并展示错误提示。

### 8.7 通用接口规则

- 金额使用最小货币单位传输，前端负责格式化。
- 时间统一返回带时区的 ISO 8601，前端转换为用户本地时间。
- 列表接口支持游标分页，避免订单或流水数量过大。
- 课时余额、批次余额和流水汇总应由服务端计算，前端不作为最终账务依据。

## 9. 加载、空态与异常处理

| 场景 | 产品表现 |
|---|---|
| 首次加载 | 显示与最终卡片结构一致的骨架屏 |
| 列表为空 | 展示对应空态文案，不显示错误提示 |
| 网络失败 | 展示“加载失败，请重试”及重试按钮 |
| 登录过期 | 提示登录状态失效并返回登录页 |
| 部分字段缺失 | 非关键字段展示“—”；关键字段缺失时不展示异常卡片并上报 |
| 重复点击 | 页面跳转期间禁止重复触发 |

## 10. 埋点需求

| 事件 | 触发时机 | 关键参数 |
|---|---|---|
| `profile_asset_entry_click` | 点击我的课时或我的订单 | `entry_type`、`student_id` |
| `lesson_type_click` | 点击剩余课时 | `lesson_type`、`balance` |
| `lesson_validity_click` | 点击去查看 | `lesson_type` |
| `lesson_filter_change` | 切换流水筛选 | `primary_filter`、`secondary_filter` |
| `order_filter_change` | 切换订单状态 | `order_status` |
| `order_card_click` | 点击订单卡片 | `order_id`、`order_status` |
| `order_detail_view` | 订单详情曝光 | `order_id`、`order_status` |
| `order_cancel_button_view` | 可取消订单的“取消订单”按钮有效曝光 | `order_id`、`order_status`、`page_source` |
| `order_cancel_click` | 点击“取消订单” | `order_id`、`order_status`、`page_source` |
| `order_cancel_dialog_view` | 取消订单二次确认弹窗曝光 | `order_id`、`order_status`、`page_source` |
| `order_cancel_dialog_dismiss` | 点击“暂不取消”或关闭确认弹窗 | `order_id`、`dismiss_method`、`page_source` |
| `order_cancel_confirm_click` | 点击“确认取消”并发起取消请求 | `order_id`、`order_status`、`page_source` |
| `order_cancel_result` | 取消订单接口返回结果 | `order_id`、`result`、`error_code`、`duration_ms`、`page_source` |

### 10.1 取消订单埋点参数定义

| 参数 | 类型 | 取值/说明 |
|---|---|---|
| `order_id` | String | 订单唯一编号 |
| `order_status` | String | 操作前订单状态，如 `pending`、`confirming` |
| `page_source` | String | 操作入口：订单列表为 `order_list`，订单详情为 `order_detail` |
| `dismiss_method` | String | `keep_order`（暂不取消）、`close`（关闭弹窗）、`mask`（点击遮罩） |
| `result` | String | `success` 或 `failed` |
| `error_code` | String | 失败时记录服务端错误码；成功时为空字符串 |
| `duration_ms` | Number | 从发起取消请求到收到结果的耗时，单位毫秒 |

#### 上报规则

- 按钮进入可视区域且可点击时，上报一次 `order_cancel_button_view`；同一页面生命周期内同一订单不重复上报。
- 列表页和详情页的取消入口必须通过 `page_source` 区分。
- 每次弹出二次确认框均上报 `order_cancel_dialog_view`。
- 用户关闭弹窗但未发起请求时，只上报 `order_cancel_dialog_dismiss`，不得上报结果事件。
- 点击确认时先上报 `order_cancel_confirm_click`；接口返回后再上报 `order_cancel_result`。
- 网络超时、业务校验失败和服务端异常均按 `failed` 上报，并携带 `error_code`。
- 埋点不得包含商品名称、用户姓名等非必要个人信息。

## 12. 上线依赖与风险

### 依赖

- 用户与当前学员身份接口。
- 课时余额、批次及流水接口。
- 订单列表和订单详情接口。
- 订单与课时类型、来源、状态枚举定义。

### 风险

- 课时余额与流水可能存在异步延迟，应以服务端账务数据为准。
- 历史订单字段不完整，需要明确兼容与降级规则。
- 订单状态命名可能与支付系统状态不完全一致，需要产品层映射。
- iPhone 不同机型安全区域不同，正式开发应读取系统 Safe Area，而非固定像素。

## 13. 后续规划

- 根据后续业务规划决定是否重新开放发票申请和协议查看。
- 支持订单搜索、时间筛选和分页加载。
- 支持课时到期提醒。
- 支持多学员切换。
- 支持从待支付订单继续支付。
- 支持退款进度和售后记录查询。
