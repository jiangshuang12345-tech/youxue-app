## 1. 需求背景

当前课程广场需要承接「选课—开课—完成学习—现实应用—获得专家支持」的完整体验，但存在三类断点：

1. 课程广场的课程价值与适合人群不够直观，首次进入不同课程时缺少引导。
2. 单个 Lesson 的学习内容与现实生活连接不足；Unit 学完后没有可执行的综合练习。
3. 专家指导仍偏向学生对话，无法充分服务家长的陪学、沟通与学习规划诉求。

本需求对课程广场 UI、Lesson 学习链路、Unit 任务卡与专家指导进行一体化改版。在不改变现有课程内容、学习进度、课程报告及底部三 Tab 主导航的前提下，建立更具探险感的学习闭环。

## 2. 产品目标

1. 用户可清晰浏览并进入五类课程，每门课程首次进入时获得一次简短的新手引导。
2. 每节 Lesson 开始前，学生可了解本节目标与五个学习环节，再进入正式学习。
3. 每个 Unit 末尾提供一张可在现实生活中完成的任务卡，帮助学生迁移本 Unit 所学。
4. 「学单词」开始页的引导文案更具体、积极，降低进入门槛。
5. 专家指导面向家长输出可执行的陪学建议，并将家长自然引导至专家课程。

## 3. 非目标

* 本期不新增课程购买、会员订阅或付费转化能力。
* 本期不改变既有 Lesson 的五个正式学习环节、题目内容、学习进度与课程报告计算规则。
* 任务卡仅提供线下/现实生活任务和提交引导，不要求 AI 自动识别任务完成情况。
* 本期不建设运营后台配置界面；任务卡与 AI 文案通过内容服务下发。
* 本期不展示学生头像，也不新增学生与专家的实时人工咨询能力。

## 4. 用户角色与核心场景

### 4.1 用户角色

* 学生：浏览课程、进入 Lesson、完成课前引导和 Unit 任务。
* 家长：在专家指导中获取针对孩子学习问题的建议，并进入专家课程。

### 4.2 核心场景

* 学生第一次打开某门课程，不知道适合自己或如何开始。
* 学生点开 Lesson 前，想快速知道今天学什么、怎么学、要多久。
* 学生完成一个 Unit，需要把词句或表达带入商场、家庭、学校等真实场景。
* 家长遇到孩子不专注、不愿开口、复习困难等问题，需要得到温和、具体、可执行的指导。

## 6. 页面与功能需求

### 6.1 课程广场 UI 改版

| 模块 | 功能 | 描述 |
| --- | --- | --- |
| 顶部工具栏 | 年级切换 | 支持「学龄前」至「六年级」切换；切换后刷新当前年级可见课程与课程文案。下拉列表展示在课程分类 Tab 上方，不能遮挡选择结果。 |
|  | 模糊搜索 | 支持按课程主标题、副标题及关键词模糊匹配；输入后实时刷新结果。无结果时展示“没有找到相关课程，换个关键词试试”。 |
| 课程分类 | 五类课程 | 展示「专家指导拔尖、校内学习同步、考试能力提升、校外素质拓展、Dino 绘本」；所有 Tab 完整可见、可点击。选中态为白底蓝字，不显示额外点击描边。 |

#### 6.1.1 每门课程新手引导

| 项目 | 规则 |
| --- | --- |
| 触发时机 | 用户首次进入某一门课程的课程详情页时触发。以 `user_id + course_id + course_version` 记录；课程版本变更后可再次触发。 |
| 展示形式 | 半透明蒙层 + 高亮当前课程 Tab + 箭头/提示卡。提示卡固定包含主标题、副标题和“我知道了”按钮。 |
| 内容要求 | 主标题不超过 8 个字；副标题不超过 30 个字。文案面向学生，使用积极、探险式表达；不得出现复杂术语、排名承诺或夸大效果。 |
| 操作 | 点击“我知道了”关闭引导，停留当前课程详情页；点击关闭按钮或蒙层也可关闭。三种方式均视为已引导，不重复弹出。 |
| 异常兜底 | 引导内容加载失败时，不阻塞课程浏览，直接展示课程详情页。 |

#### 6.1.2 新手引导固定文案

提示卡样式按原型统一：主标题 + 副标题 + 主按钮。主标题用于一句话概括课程价值；副标题用于说明学习收获或学习方式。底部主按钮统一为“我知道了”。除下表约定文案外，不在客户端临时改写，确保同一课程的首访体验一致。

| 课程 | 主标题（≤8字） | 副标题（≤30字） | 按钮 |
| --- | --- | --- | --- |
| 专家指导拔尖 | 专家带你学 | 跟着权威专家掌握关键方法，针对薄弱点逐步提升。 | 我知道了 |
| 校内学习同步 | 校内同步学 | 紧贴学校进度学习，帮你把单词和句子学得更扎实。 | 我知道了 |
| 考试能力提升 | 闯关提能力 | 练读题、练思考、练表达，从容迎接每一次挑战。 | 我知道了 |
| 校外素质拓展 | 探索大世界 | 探索自然、科技和艺术，用英语认识更大的世界。 | 我知道了 |
| Dino 绘本 | Dino讲故事 | 跟着 Dino 读绘本，在有趣故事里学会听、说和表达。 | 我知道了 |

#### 6.1.3 展示与排版规则

| 项目 | 规则 |
| --- | --- |
| 主标题 | 使用下表的固定引导标题，单行展示，不超过 8 个字；如屏幕宽度不足，优先缩小字号。 |
| 副标题 | 使用下表的固定副标题；不展示“课程价值”“建议学习方式”等段落标签。 |
| 文案长度 | 副标题不超过 30 个字，横屏手机最多两行；必要时按语义换行。 |
| 高亮对象 | 仅高亮当前课程 Tab；其他 Tab 与背景降亮，不能占据高亮区域或遮挡提示卡。 |
| 箭头 | 箭头尖端明确指向当前课程 Tab 的中心区域；不同课程切换时随 Tab 位置同步变化。 |
| 关闭后状态 | 关闭蒙层后，当前课程 Tab 保持白底蓝字选中态，不保留蓝色描边、锁头或空白占位。 |

### 6.2 Lesson 课前引导

#### 6.2.1 入口与流程

1. 用户点击任一未完成或可复习的 Lesson。
2. 先进入「课前引导」页，不直接进入正式学习。
3. 用户点击“准备出发”后进入该 Lesson 的第一个正式环节「学单词」。
4. 返回时回到 Lesson/Unit 列表；不允许绕过课前引导影响正常进度。

#### 6.2.2 页面内容

| 模块 | 描述 |
| --- | --- |
| 本节主题 | 展示 Lesson 标题、Unit 标识和一张主题视觉图。 |
| 本节知识简介 | 用 40—70 字说明“今天会学什么、能在哪儿用到”，优先关联具体生活情境。 |
| 学习环节 | 固定展示五个环节：学单词、读句子、做练习、听故事、情景对话；每项展示图标与一句简短说明。 |
| 学习路径 | 五个环节按顺序以路径式卡片呈现；视觉顺序必须和正式 Lesson 一致。 |
| 主按钮 | 固定按钮“准备出发”，点击进入学单词；加载中不可重复点击。 |

### 6.3 「学单词」开始页文案改版

| 项目 | 规则 |
| --- | --- |
| 展示时机 | 用户从课前引导点击“准备出发”后，进入「学单词」的开始介绍页。 |
| 文案目标 | 让学生知道本环节会认识哪些核心词，并以任务感激发开始意愿。 |
| 文案结构 | 标题：固定为“把单词装进探险背包”；正文：30—50 字，包含主题、词汇数量（可取范围）和一个鼓励性动作指令。 |
| 主按钮 | “开始学单词”；点击后进入现有单词学习内容。 |
| 边界 | 不虚构词汇或词义；当词汇数据缺失时使用兜底文案“准备好认识今天的新朋友吧”。 |

### 6.4 Unit 任务卡

#### 6.4.1 触发与位置

| 项目 | 规则 |
| --- | --- |
| 插入位置 | 每个 Unit 的最后一个 Lesson 完成后，在 Unit 学习路径中展示一张任务卡；不插入在 Unit 中间。 |
| 解锁条件 | 最后一个 Lesson 达到既有完成态后解锁；未完成时展示任务卡入口但不可开始，并提示“完成本单元课程后解锁”。 |
| 进入方式 | 点击任务卡进入任务详情；返回后保留 Unit 列表位置与学习进度。 |
| 完成方式 | 学生与家长在线下完成任务后，点击“我完成啦”即可标记完成；本期不做强制拍照、录音或 AI 判定。 |
| 重做 | 已完成任务可再次查看和重做，不影响已完成状态。 |

#### 6.4.2 任务卡内容与规则

| 字段 | 规则 |
| --- | --- |
| 任务标题 | 8—16 字，使用行动导向语言，如“商场标识小侦探”。 |
| 任务目标 | 一句话说明任务会复习的主题、词汇或表达。 |
| 准备物品 | 最多 3 项；优先为家中可获得物品，不得要求购买。 |
| 任务步骤 | 3—5 步；每一步可被儿童和家长理解、可在 10—20 分钟内完成。 |
| 说一说 | 提供 1—3 句可直接练习的目标句；与本 Unit 词句一致。 |
| 安全提示 | 涉及外出、厨房、交通、陌生人、拍摄等场景时必须给出家长陪同/安全提醒。 |
| 任务状态 | 未解锁、待完成、已完成。 |

### 6.5 专家指导（家长侧）

| 模块 | 功能 | 描述 |
| --- | --- | --- |
| 页面定位 | 家长指导 | 页面所有称呼、问题和建议均面向家长，不再以学生为对话对象。 |
| 头像 | 删除学生头像 | 删除学生头像及与学生身份绑定的开场表达；可保留龚老师的专家形象。 |
| 开场内容 | 专家欢迎语 | 示例：“家长你好，我是龚亚夫。引导孩子学习英语要讲究方法，你有什么问题都可以问我哦～” |
| 快捷话题 | 家长常见问题 | 至少展示 3 个话题；首条固定为“孩子不专注学习怎么办”，其余话题由服务基于首条/上下文生成或由运营配置。 |
| AI 建议 | 专家回复 | 输出适龄、温和、可操作的陪学建议；不作诊断、承诺学习效果或贬低孩子。 |
| 专家课程入口 | 跳转 | 在“定制专属计划”下方增加与其同尺寸的“专家课程”卡片，带专家相关图标；点击进入新版课程广场，不跳转到旧的专家课程列表页。 |

## 7. AI 内容生成规范与 Prompt

### 7.1 通用调用规则

* 服务端传入结构化课程数据，模型仅负责生成文案；客户端不得拼接自由文本直接调用模型。
* 模型输出必须为 JSON，不得包含 Markdown、解释性前后缀或未定义字段。
* 生成结果需经过敏感词、安全规则与 JSON Schema 校验；校验失败时使用对应兜底文案。
* 不得生成恐吓、羞辱、比较性评价、医疗/心理诊断、购买要求、危险活动或需要陌生人参与的任务。
* 使用简体中文，语言适合 3—12 岁儿童及其家长理解；具体年龄以 `age_band` 为准。

### 7.2 Unit 任务卡 Prompt

**输入变量**

`{{unit_title}}`、`{{unit_theme}}`、`{{age_band}}`、`{{grade}}`、`{{key_words}}`、`{{key_sentences}}`、`{{lesson_summary}}`、`{{available_scenes}}`、`{{visual_style}}`

```text
你是 VIPKID 优学的儿童英语活动设计师。请基于给定 Unit 信息，设计一个孩子能在现实生活中完成的英语任务卡。

要求：
1. 任务必须围绕本 Unit 主题、核心单词和句型，不得引入未提供的英语知识。
2. 在家庭、学校或常见公共场景中可完成；时长 10—20 分钟；孩子可在家长陪同下完成。
3. 给出 3—5 个清晰步骤、最多 3 项准备物品，以及 1—3 句可开口练习的目标句。
4. 活动要有探险感，但不能要求购买、独自外出、接触陌生人、危险操作、拍摄上传或分享隐私。
5. 如任务涉及外出或公共场所，在 safety_tip 中提醒家长陪同；否则返回空字符串。
6. 同时产出用于生成任务卡插画的 `cover_image.prompt`，插画应表现“任务正在进行”的一个瞬间，不是步骤拼图或文字海报。
7. `cover_image.prompt` 中必须写清场景、人物动作、关键道具、画面构图和视觉风格；画面中不得出现文字、字母、数字、题目、答案、品牌标识或水印。
8. 插画须采用“优学探险任务卡”视觉：高品质 3D 卡通渲染、明亮饱和的暖黄/橙/蓝/青配色、柔和高光、圆润材质、轻探险感。Dino 出场时使用圆润黄橙色小恐龙探险家形象（大眼睛、友好笑容、轻便探险背包），横版 16:9 构图，主体位于画面中部或右侧，为左侧文案预留干净留白。
9. 插画不得表现独自外出、危险动作、陌生人互动、隐私拍摄、购买行为或与 Unit 无关的物品；涉及公共场景时，画面内必须出现家长陪同。
10. 只返回合法 JSON，不要输出任何其他文字。

输入：
Unit 标题：{{unit_title}}
主题：{{unit_theme}}
年龄段：{{age_band}}
年级：{{grade}}
核心单词：{{key_words}}
核心句型：{{key_sentences}}
学习内容摘要：{{lesson_summary}}
可用场景：{{available_scenes}}
视觉风格：{{visual_style}}

输出 JSON：
{
  "title": "8—16字任务标题",
  "goal": "不超过40字",
  "materials": ["物品1"],
  "steps": ["步骤1", "步骤2", "步骤3"],
  "say_it": ["英文目标句1"],
  "parent_tip": "不超过50字的陪同建议",
  "safety_tip": "安全提示或空字符串",
  "cover_image": {
    "generation_required": true,
    "style_reference": "youxue_task_card_v1",
    "aspect_ratio": "16:9",
    "output_format": "png",
    "prompt": "中文插画生成提示词，120—220字",
    "negative_prompt": "文字、字母、数字、水印、品牌logo、任务卡角标、白色卡框、危险动作、独自外出、陌生人、隐私拍摄、低清晰度"
  }
}
```

#### 7.2.1 图文任务卡视觉基准

| 维度 | 统一规则 |
| --- | --- |
| 整体风格 | 与参考任务卡一致：高品质 3D 儿童卡通、圆润可爱、明亮饱和、生活场景真实但带轻探险氛围；避免扁平插画、写实摄影、暗黑或水墨风。 |
| 主角 | 优先使用 Dino 作为任务引导者：圆润黄橙色小恐龙、大眼睛、友好笑容、轻便探险背包；Dino 的动作必须服务任务，如指路、观察、寻找、记录或与家长共同完成任务。 |
| 场景 | 使用与 Unit 主题一致的生活空间；场景要有可辨认的核心物件与空间纵深，例如商场导视、自然观察区、家庭阅读角、校园活动区。 |
| 色彩与光影 | 主色为暖黄、橙、天蓝、青绿，可搭配少量紫色点缀；光线明亮柔和，有轻微玻璃/塑料质感高光，不使用灰暗滤镜。 |
| 构图 | 横版 16:9；Dino、儿童和关键任务物件位于中部或右侧，左侧保留约 35% 低细节区域给客户端叠加文字。画面信息聚焦，不拼贴多个分镜。 |
| 客户端卡框 | 客户端负责添加白色圆角任务卡、黄色“任务卡”角标、标题、任务目标与地点标签；生成图只作为卡面插图，不生成任何 UI 或文字。 |

当内容服务与图片服务分开调用时，先使用 7.2 生成任务卡文字，再将其 JSON 结果代入以下 Prompt 生成卡面插画。`{{visual_style}}` 默认值为“优学探险任务卡风格：高品质 3D 卡通渲染，圆润黄橙色 Dino 小恐龙探险家，大眼睛、友好笑容、轻便背包；暖黄、橙、天蓝、青绿的明亮饱和配色，柔和高光，真实生活场景与轻探险感”。

```text

必须遵守：
1. 画幅为横版 16:9，使用高品质 3D 儿童卡通渲染；画风必须与“优学探险任务卡”一致：圆润造型、明亮饱和、暖黄/橙/天蓝/青绿配色、柔和高光和轻探险感。不要生成扁平矢量图、写实摄影、暗黑画风或复杂拼贴。

3. 清楚表现儿童/Dino 正在完成的核心动作，以及任务所需的关键道具；道具数量不超过 3 件，不出现购买、食物浪费、危险器械或与任务无关的装饰。
4. 主体置于中部或右侧；左侧预留约 35% 干净、低细节的留白，供客户端叠加标题和目标文字。画面须有适度景深和空间纵深，但主体清晰、表情自然。

主题：{{unit_theme}}

准备物品：{{materials}}
适用年龄：{{age_band}}
可用场景：{{available_scenes}}
安全提示：{{safety_tip}}
视觉风格：{{visual_style}}

请只输出用于图片生成的中文提示词，不要解释。
```

#### 7.2.3 图片生成请求与最终输出

任务内容模型不直接返回图片二进制；服务端必须将上一步的 `cover_image.prompt` 传给图片生成模型，获得真实卡面图片并写入图片资产服务。禁止只把 Prompt 下发给客户端、由客户端自行生成或展示。

**图片模型请求（服务端）**

```json
{
  "model": "image-generation-model",
  "prompt": "{{task.cover_image.prompt}}",
  "negative_prompt": "{{task.cover_image.negative_prompt}}",
  "reference_image_id": "youxue_task_card_v1",
  "size": "1536x864",
  "aspect_ratio": "16:9",
  "output_format": "png",
  "n": 1
}
```

`reference_image_id` 指向已在图片服务中配置的优学任务卡风格参考图，作为视觉一致性的必传参考；图片模型的调用能力若不支持负向 Prompt 或参考图，必须把对应约束合并写入 `prompt`，不得省略。

**下发给客户端的最终任务卡 JSON**

```json
{
  "task_id": "{{task_id}}",
  "title": "{{title}}",
  "goal": "{{goal}}",
  "materials": ["{{materials}}"],
  "steps": ["{{steps}}"],
  "say_it": ["{{say_it}}"],
  "parent_tip": "{{parent_tip}}",
  "safety_tip": "{{safety_tip}}",
  "cover_image_url": "https://{{cdn}}/{{asset_id}}.png",
  "cover_image_status": "ready"
}
```

| 字段 | 规则 |
| --- | --- |
| `cover_image_url` | 必须为图片模型生成并上传后的 CDN 地址；客户端直接加载该图片，不再接收或生成 Prompt。 |
| `cover_image_status` | `generating`：显示预置任务卡骨架/占位图；`ready`：展示生成图；`failed`：展示预置探险插画。 |
| 图片校验 | 上传前校验 PNG、16:9、无可读文字/水印/二维码、主体清晰、符合任务场景与安全规则。校验不通过时最多重试 1 次；仍失败走预置插画。 |
| 缓存 | 同一 `unit_id + content_version` 复用同一张已审核卡面，避免用户刷新时图文不一致或重复生成。 |

#### 7.2.4 图文任务卡调用顺序

1. 调用 7.2，生成可展示的任务文字和 `cover_image` 图片生成参数。
2. 对文字 JSON 执行字段、字数、安全和 Unit 词句一致性校验。
3. 通过校验后，服务端按 7.2.3 调用图片生成模型，并将生成 PNG 上传为任务卡图片资产。
4. 图片审核通过后，服务端将文字字段和 `cover_image_url` 一并下发；客户端将插画置于任务卡顶部/右侧，叠加任务标题、目标与入口按钮。
5. 图片生成或审核失败时使用预置探险插画兜底，不影响任务文字展示；禁止将模型生成的文字直接烘焙进图片。

## 8. 状态、异常与兼容性

| 场景 | 产品表现 |

## 10. 验收标准

### 10.1 课程广场与新手引导

* [ ] 五类课程 Tab 在目标横屏设备上均完整展示、可点击，且不出现点击外框。
* [ ] 年级切换、模糊搜索和课程卡片跳转符合现有交互；刷新后页面可正常加载。
* [ ] 每门课程首次进入时仅展示一次新手引导；关闭后不跨页残留。

### 10.2 Lesson 课前引导与学单词

* [ ] 任一 Lesson 进入正式学习前均先展示课前引导。
* [ ] 课前引导固定展示“学单词、读句子、做练习、听故事、情景对话”五环节。
* [ ] 点击“准备出发”进入原有学单词内容，不影响既有学习进度。
* [ ] 学单词开始介绍符合固定标题、主题和词汇数量约束；数据缺失可正确兜底。

### 10.3 Unit 任务卡

* [ ] 每个 Unit 仅在最后一个 Lesson 完成后解锁一张任务卡。
* [ ] 任务卡包含标题、目标、准备物品、3—5 步、开口练习句与必要的安全提醒。
* [ ] 点击“我完成啦”可将任务标记为已完成；可再次查看，不影响学习进度。
* [ ] AI 生成失败时可降级为模板任务，不阻塞 Unit 学习。

### 10.4 专家指导

* [ ] 页面删除学生头像，所有开场、话题及回复均面向家长。
* [ ] 专家建议含共情回应、3 条可执行建议、可选课程推荐和 2 个后续话题。
* [ ] “专家课程”入口位于“定制专属计划”下方，点击进入新版课程广场。
